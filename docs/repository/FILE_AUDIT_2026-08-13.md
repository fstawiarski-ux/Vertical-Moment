## Migration candidates — not deletion candidates yet

### Heavy source assets

Examples include a ~121 MB OBJ, ~29.9 MB source GLB, ~22.7 MB diffuse texture and large production videos. Large binary patterns are already configured for Git LFS, but the preferred long-term pattern is:

1. verified external master in Drive/R2/archive;
2. checksum and rights/status manifest in Git;
3. optimized, versioned web derivative in R2 or the reviewed deploy bundle;
4. removal from active Git paths only after restore testing.

Do not rewrite Git history as part of ordinary product cleanup.

### Root `index.html`

The 277 KB root static explorer predates the current Next application. It is a likely archive candidate, but it must first be compared with preserved static prototypes and checked for unique behavior/assets. Move it to a clearly named archive in a focused review; do not silently delete it.

### README-only reserved folders

`app/`, `guidebook/`, `infrastructure/`, `media/`, `scripts/`, `tests/` and `viewer/` are small control placeholders. Their size is negligible. Consolidate or repurpose them only when the target workspace exists; deleting them provides no meaningful cleanup benefit.

### Historical documentation

Some docs refer to completed feature branches. Preserve the historical record, but mark it historical or replace operational instructions with links to `main` and the product map.

## Generated or rebuildable material

- `website/public/sw.js` is generated by the Serwist build and must not be hand-edited or included in source patches.
- `website/public/data/v1` is synchronized from `database/api/v1` by repository scripts; avoid treating generated copies as independent canonical data.
- Next/OpenNext build directories, caches and local dependency trees must remain ignored.

## Clean-repository acceptance criteria

- Every top-level path has an owner and status.
- Public-site and PWA code paths are documented and later physically separated.
- Canonical data is not duplicated.
- Heavy masters have tested external recovery plus checksums before active-path removal.
- Generated files are not mistaken for source.
- Historical branches are removed only after their merged PRs/checkpoints are preserved.
- No “mystery ZIP” or unclassified prototype is committed to make it easier to find.
